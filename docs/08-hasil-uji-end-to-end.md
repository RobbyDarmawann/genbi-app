## 3. Daftar Cacat Temuan (_Defect Log_)

Dari eksekusi menyeluruh 30 skenario, **tidak ditemukan cacat kritis maupun fungsional** pada alur bisnis (pendaftaran, absensi, kalkulasi poin, peninjauan, penguncian, dan ekspor).

Namun, tercatat satu catatan observasi non-kritis terkait penyajian UI publik:

### Observasi OBS-01: Filter Kategori/Status pada Halaman Jadwal Publik

- **ID Skenario Terkait**: E2E-02
- **Tingkat Keparahan**: Rendah (Peningkatan UX / Non-Blocking)
- **Langkah Reproduksi**: Buka halaman `http://127.0.0.1:8000/jadwal` sebagai Guest.
- **Hasil Aktual**: Halaman memiliki input pencarian teks (`q`), namun belum menyediakan dropdown filter status (misal: "Semua", "Akan Datang", "Selesai").
- **Hasil Diharapkan**: Guest dapat memfilter jadwal berdasarkan rentang waktu atau status secara cepat selain menggunakan pencarian kata kunci.
- **Dugaan File/Komponen**: `app/Http/Controllers/Public/JadwalController.php` & `resources/js/pages/public/jadwal.tsx`.
- **Usulan Tindak Lanjut (Terpisah)**: Menambahkan filter query parameter `status` pada `JadwalController` dan dropdown filter pada tampilan `jadwal.tsx` pasca-demo.

## 4. Panduan Langkah Uji Manual di Perangkat Fisik (Smartphone)

Skenario **E2E-18** memerlukan interaksi langsung dengan perangkat keras dan API browser seluler (`navigator.geolocation` dan `navigator.mediaDevices.getUserMedia`). Lakukan langkah berikut di smartphone nyata yang terhubung ke jaringan lokal server:

### Persiapan Perangkat:

1. Pastikan smartphone berada dalam satu jaringan Wi-Fi lokal dengan komputer pengembang.
2. Buka browser mobile (Google Chrome / Safari) dan akses URL aplikasi (misal: `http://<IP-Lokal-Komputer>:8000/`).
3. Login menggunakan akun mahasiswa demo: `mhs001` (password: `password`).

### Uji 1: Penanganan Penolakan Izin Lokasi (GPS)

1. Buka menu aktivitas kegiatan yang sedang dibuka absensinya (misal Kegiatan Demo #5).
2. Tekan tombol **"Buka Absensi"**.
3. Saat browser memunculkan dialog pop-up _"Aplikasi ingin mengetahui lokasi Anda"_, pilih **"Blokir" / "Jangan Izinkan"**.
4. **Hasil yang Harus Diverifikasi**: Aplikasi tidak crash/blank putih; muncul alert banner ramah bertuliskan bahwa koordinat GPS wajib diaktifkan untuk menghitung radius absensi.

### Uji 2: Penanganan Penolakan Izin Kamera Selfie

1. Refresh halaman absensi dan berikan izin lokasi.
2. Saat browser meminta izin akses kamera (_"Aplikasi ingin menggunakan kamera Anda"_), pilih **"Blokir"**.
3. **Hasil yang Harus Diverifikasi**: Tampil panduan untuk mengizinkan kamera pada pengaturan situs browser; tombol ambil foto dinonaktifkan secara aman.

### Uji 3: Penanganan GPS Akurasi Buruk (> 100 Meter)

1. Lakukan pengujian di dalam ruangan beton tertutup (basement/ruang tanpa sinyal satelit) atau aktifkan mode GPS hemat daya sehingga akurasi terbaca > 100m.
2. Ambil foto selfie dan kirim absensi.
3. **Hasil yang Harus Diverifikasi**: Absensi diterima dengan pesan status **"Menunggu Tinjauan Internal Manajemen"** karena akurasi GPS di atas ambang batas toleransi (100 m); saldo poin mahasiswa belum bertambah sampai disetujui IM.

### Uji 4: Tampilan Responsif Mobile Viewport 360px

1. Uji halaman pada layar ponsel resolusi kompak (lebar 360px).
2. Periksa form absensi, video viewfinder kamera, tombol ambil foto, dan kartu detail kegiatan.
3. **Hasil yang Harus Diverifikasi**: Tombol aksi memiliki tinggi minimal 44px (`h-11 md:h-9`), tidak ada elemen teks atau form yang terpotong secara horizontal (_no horizontal layout shift_).

## 5. Putusan Akhir

Berdasarkan seluruh bukti eksekusi otomatis, kelulusan seluruh skenario alur inti (Pendaftaran, Geofencing, Ledger Poin Atomik, Penguncian, dan Ekspor), serta integritas aturan arsitektur sistem:

# **PUTUSAN: SIAP DENGAN CATATAN**

### Alasan Putusan:

1. **Seluruh skenario inti A–F LULUS (29/30 skenario)** tanpa satu pun kegagalan logika bisnis, kebocoran data pribadi (UU PDP No. 27/2022 terpenuhi), maupun pelanggaran arsitektur.
2. **Catatan**: Skenario **E2E-18** berstatus **BLOKIR** khusus untuk verifikasi sensor hardware fisik pada ponsel nyata (izin kamera dan izin lokasi), yang wajib dipraktikkan langsung pada unit smartphone saat demonstrasi UAS di hadapan penguji/dosen.
